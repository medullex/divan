## Устройство

Node.js без внешних зависимостей (`npm install` ничего не ставит). Запуск: `npm start` → http://localhost:3000

| Файл | Что делает |
|---|---|
| `server.js` | HTTP + WebSocket: комнаты, ведущий, синхронизация плеера, очередь, пароль, чат, поиск Rutube, TURN, ретранслятор видео |
| `miniws.js` | Свой минимальный WebSocket-сервер (текст + двоичные сообщения) |
| `accounts.js` | Аккаунты, друзья, онлайн-статус, приглашения, фото-аватарки (Upstash Redis через REST) |
| `stats.js` | Список посетителей для владельца (анонимная метка браузера, без IP) |
| `public/index.html` | Весь фронтенд одной страницей (лобби + комната) |
| `public/stats.html` | Страница /stats — список посетителей (видит только STATS_USER) |
| `public/nettest.html` | Проверка сети: проходят ли STUN/TURN из сети пользователя |
| `public/sw.js`, `manifest.webmanifest`, `icons/` | PWA (установка как приложение) |

### Источники видео
1. **Rutube** — поиск по названию (`/api/search`), встроенный плеер, управление через postMessage.
2. **VK Видео** — по ссылке, плеер VK.VideoPlayer (js_api=1).
3. **Фильм с компьютера** — ведущий выбирает файл, он загружается на сервер (POST `/api/upload?t=<токен>`,
   тело — сам файл через XMLHttpRequest, пишется потоком в `os.tmpdir()/divan-uploads`), все видят проценты.
   Потом у зрителей `<video src="/media/<id>">` (Range/206 — нужно iPhone), загрузивший смотрит локальную копию (blob).
   Синхронизация — тот же `sync`, что у Rutube/VK (плеер `filePlayer` в index.html с тем же интерфейсом).
   Файл удаляется: через 20 с после ухода загрузившего (метка `vid`; перезагрузка страницы не считается),
   при выборе другого видео, при отмене/обрыве загрузки. Передача роли ведущего файл НЕ удаляет.
   WS: `upreq{name,size}` → `uptoken{token,gen}` / `upfail{text}`; `upprog{gen,loaded,total}`; `upcancel`;
   в `room` есть `upload{gen,name,total,loaded}`, фильм — `media{kind:'file',id,title,size,gen,n}`.
   WebRTC и ретранслятор «через сервер» удалены (19.10.2026). `/config` и nettest.html остались, но для видео не нужны.

### Комнаты и ведущий
- Каждый браузер имеет анонимную метку `vid` (localStorage `divan-vid`), передаётся в `hello`.
- Тот же `vid` повторно в комнате → старая копия удаляется (сообщение `replaced`).
- Создатель комнаты (`ownerVid`) при возвращении снова становится ведущим; при уходе ведущего роль ждёт его 20 с.

### Переменные окружения (задаются в Render → Environment, значения не просить в чате)
- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — база (аккаунты, друзья, посетители)
- `METERED_TURN_URL` — ссылка Metered вида `https://<app>.metered.live/api/v1/turn/credentials?apiKey=…`
- `STATS_USER` — ник владельца на сайте (доступ к /stats); возможно ещё не задан
- `MAX_UPLOAD_MB` — предел размера фильма (по умолчанию 2500)
- (опционально) `CF_TURN_KEY_ID` + `CF_TURN_TOKEN` — TURN Cloudflare вместо Metered

## Тестирование локально
- Playwright + Chromium: в обычном Chromium нет H.264, для тестов воспроизведения берите .webm.
  Медленную загрузку удобно имитировать через CDP `Network.emulateNetworkConditions` (uploadThroughput).
- Для аккаунтов без Upstash можно поднять простую заглушку Redis REST (команды HGETALL/HSET/HSETNX/HMGET/SET/GET/DEL/
  SADD/SREM/SMEMBERS/SISMEMBER/SCARD/HINCRBY/ZADD/ZREVRANGE/INCR/EXISTS/EXPIRE + /pipeline).

## Правила
- Не создавать аккаунты и не вводить пароли/ключи за пользователя; секреты он вставляет сам.
- Перед необратимыми действиями (удаление, смена настроек) — спрашивать.
- Пользователь в России: Cloudflare-сервисы и зарубежные TURN могут не работать; Rutube/VK — работают.
